## Current position

The repository is at the **speech-input prototype stage**, with a standalone intent-classification module and a basic transcript-to-LLM path. It has not yet reached the architecture's routed, evidence-backed reasoning stage.

Code exists for microphone capture, English/Hindi transcription, Hinglish display, optional speaker diarization, speaker-keyed transcript buffering, periodic LLM dispatch, terminal output, and diagnostic logging. These are implemented capabilities, not a verified end-to-end deployment: there is a startup import defect and runtime dependencies are incomplete in the inspected environment.

The most useful next milestone is:

> An ordered transcript enters one orchestrator, is split into utterances and classified, then produces either a cited answer, an evidence-backed claim verdict, or an explicit unsupported-route result. Results retain their session, speaker, and utterance IDs and survive restart.

Do not estimate completion from the volume of Whisper code. Most of `whisper/` supplies the speech-recognition foundation; the larger reasoning, ethics, memory, and delivery system in the diagram remains to be built. A single completion percentage would obscure that distinction.

## Actual flows today

**Basic script:** microphone -> accumulated audio -> faster-whisper -> finalized text -> synchronous Groq fact-check request -> terminal/log.

**Diarized script, once startup is repaired:** microphone -> faster-whisper -> optional rolling-window diarization -> per-speaker text buffer -> periodic worker -> LLM thread -> terminal/log.

**Classifier:** direct Python caller -> `SentenceClassifier` -> classification dictionary. This path is separate from both live flows.

## Defects and gaps to address first

1. **Startup import failure:** `live_whisper_diarize.py:18` unconditionally executes `from whisper import logger` after `import logger`. There is no `whisper/logger.py` or corresponding package export. Use one consistent application logger import. This also affects Windows-spawn imports of the entry module.
2. **Unreproducible diarization dependency:** the script adds `../whisperx` to `sys.path`, but that sibling project is outside this repository and `whisperx` is not declared in `requirements.txt`. Declaring `pyannote.audio` alone does not provide the imported `whisperx.diarize` module. Package the dependency or isolate a direct pyannote adapter, and document model access requirements after verifying them.
3. **Classifier tests are not tests:** `tests/test_sentence_classifier.py:27` invokes a real classifier at import time and prints the result. There are no test functions/assertions. Collection can load/download a model and currently fails without `transformers`. Replace this with isolated mock tests; put real-model checks behind an explicit integration-test option.
4. **Dispatch loses failed work:** `_get_new_speakers()` advances pointers before the LLM succeeds (`llm_pipeline.py:141`). Failed calls are logged but not returned to pending work. Introduce stable job IDs, pending/in-flight/succeeded/failed states, acknowledgment, bounded retries, and idempotent result writes.
5. **Turn order is lost:** grouping all new utterances by speaker changes interleaved dialogue into speaker monologues. Store a chronological event stream; derive speaker views from it. Keep timestamps and original text alongside display transliterations.
6. **Shutdown can omit final work:** the worker exits on the stop signal without extracting pending buffered utterances. Audio not yet finalized can also be omitted. Cleanup runs only in the KeyboardInterrupt branch, not reliably after other failures. Flush final work and close workers/Manager in `finally`, with a global shutdown deadline and explicit unresolved-job reporting.
7. **Resource bounds are incomplete:** transcript lists grow for the full session, audio queues are unbounded, and every dispatch can start another thread. Bound queues, retained context, in-flight jobs, and request duration. The basic script's synchronous LLM call also pauses audio consumption.
8. **Speaker identity is provisional:** the rolling diarization cap is actually 30 seconds, despite a comment saying five minutes (`live_whisper_diarize.py:487`). Relabeling independently over changing windows does not establish stable session identities. Window/chunk timing and behavior when processing falls behind also need regression coverage.
9. **Logging path and process coordination:** `logger.py:54` treats a containing folder named `whisper` as a package folder and moves the log destination to its parent. Here that resolves to `stealth_project/vague.log`, outside this repository. The lock coordinates threads within each process only. Configure a workspace-local destination and use a single log writer; add IDs because `log_llm_response()` accepts but does not record its `speaker_block` argument.
10. **Packaging/documentation lag behind the application:** README and `pyproject.toml` describe the Whisper library; application setup, routes, runtime dependencies, and operating procedure are missing. `requirements.txt` includes application packages absent from project dependencies. Dependencies are broadly unpinned; `.gitignore` omits `venv/` and runtime log patterns. Resolve environment/package boundaries before claiming reproducible setup.
11. **Intent labels need a clear contract:** classify the speech act separately from whether a proposition is true. A `fact` classification is not a verified verdict. Add opinion/debate and neutral/unsupported handling, define overlapping question/query semantics, and evaluate English, Hindi, and Hinglish examples before selecting thresholds.

## Recommended sequence

### Phase 0 — Make the existing prototype reproducible

- Fix the logger import and destination; resolve the undeclared WhisperX dependency.
- Document one supported runtime environment after checking compatibility; the inspected venv reports Python 3.14.5, which is not itself evidence that the full stack works.
- Define application/runtime and development dependencies, lock a working environment, and add a credential-free `.env.example` listing required variable names.
- Make live entry points importable without starting capture or loading models. Add CLI help, missing-configuration checks, and clear unavailable-diarization behavior.
- Replace the classifier demonstration with real unit tests; add focused buffer, failed-dispatch, and shutdown tests.

**Exit check:** fresh setup succeeds; both entry points show help; a prerecorded fixture can produce a transcript; mock LLM success/failure paths terminate cleanly; tests do not download models during collection.

### Phase 1 — Build the context and routing backbone (next functional step)

- Introduce an ordered utterance record: `session_id`, `utterance_id`, sequence number, speaker ID, start/end time, language, original text, display text, and finalization state.
- Segment finalized text into meaningful utterances while retaining links to the source audio chunk. Avoid routing an entire multi-topic 20-second speaker block as one intent.
- Create a text-first orchestrator independent of microphone/model imports. Keep the live scripts as adapters that submit finalized records.
- Invoke the existing classifier inside the worker, outside the audio callback. Map question/query to answer retrieval, factual assertions/claims to verification, and opinion/debate to the panel route. Use confidence and unsupported/ambiguous results to abstain or request clarification.
- Add a bounded recent-context window, durable jobs, acknowledgment, timeouts, backpressure, and reliable final draining. Manager proxy calls do not make compound read-modify-write sequences atomic; retain a single-writer contract or synchronize those operations.
- Use a lightweight durable store, such as SQLite, for sessions, utterances, jobs, and results. This is a proposed starting design, not an existing dependency.

**Exit check:** a deterministic replay of interleaved speakers preserves turn order, selects the expected route, survives a failed request/restart, and never blocks the capture callback. Unimplemented handlers return explicit status instead of fabricated answers.

### Phase 2 — Deliver an evidence-backed question/claim MVP

- Define a shared retrieval interface. Start with a small curated local corpus and deterministic fixtures; add document/web/archive adapters as required by the target use case.
- Store evidence IDs, source title/location, source date where available, retrieval time, exact supporting passages, and retrieval provenance. Rank relevant context within a token budget.
- For questions, synthesize an answer from retrieved evidence and attach resolvable references.
- For claims, extract individual propositions and compare supporting/contradicting evidence. Return `TRUE`, `FALSE`, or `UNCERTAIN` with rationale, evidence IDs, limitations, and per-claim attribution. Missing or conflicting evidence must permit `UNCERTAIN`.
- Generate a structured result first, then render readable terminal text. Persist evidence and decisions with their utterance IDs.

**Exit check:** replay cases cover a supported answer, supported/refuted claims, conflicting sources, no evidence, multiple claims, and retrieval failure. Every citation resolves to a stored source passage; unsupported assertions do not become confident verdicts.

### Phase 3 — Add the opinion/debate panel and integrator

- Define technical, economic, and ethical panelist interfaces with explicit roles and bounded concurrent execution.
- Give panelists the same relevant evidence and chronological context. Return conclusions, assumptions, evidence references, disagreements, and limitations.
- Add an integrator that preserves material disagreement and partial failures when producing one response.

**Exit check:** one failed panelist does not halt the session; the final result preserves source attribution and distinguishes factual evidence from evaluative judgments.

### Phase 4 — Define and implement ethics and feedback

- First document what the diagram's Materialism, PassionIT, and civilizational/religious dimensions mean, including criteria, scale, weighting, provenance, and examples. These meanings cannot be inferred reliably from their labels.
- Implement a versioned rubric with explanations per dimension and explicit unavailable/insufficient-context states. Store any aggregate score together with its rationale and rubric version.
- Apply the ethical evaluation to all relevant route outputs and pass its findings into the integrator, following the diagram's intended flow.
- Add feedback checks for missing citations, incomplete reasoning, and rubric coverage. Bound revision count and latency so the feedback loop always terminates.

**Exit check:** evaluated examples are reviewable by a person; results expose dimension-level rationale; the loop reaches either a validated response or an explicit unresolved result.

### Phase 5 — Complete delivery, memory, audit, and analytics

- Add a delivery API/event channel and audience UI, followed by voice output if required. Keep terminal delivery available for diagnostics.
- Extend the session store into deliberate short-term context retrieval and long-term evidence/decision/ethics retrieval, with defined retention and access behavior.
- Record correlated, structured events through one writer. Add authentication and tamper-evident hash chaining with a verification procedure; describe the integrity guarantees accurately.
- Build analytics from persisted events: route distribution, latency, queue backlog, failures, uncertain verdicts, source coverage, panel performance, and rubric trends.

**Exit check:** an audience client receives correlated results, sessions can be reconstructed after restart, audit modification is detectable within the stated threat model, and reported metrics can be traced to stored records.
